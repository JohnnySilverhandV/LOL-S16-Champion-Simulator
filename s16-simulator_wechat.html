从一张八强截图到可玩的 S16 冠军模拟器：单文件 HTML 的级联状态机设计

本文记录一个真实小项目的完整过程：用户给了一张 S16 全球总决赛八强对阵截图，要求做一个可模拟、可调比分、锁定赛果的淘汰赛对阵图。最终交付是一个约 640 行的单文件 HTML，零依赖，同步到了 GitHub、码云双仓库与三种在线入口。文章不讲流水账，只讲设计决策和真实踩坑。

在线试玩：https://s16-champion-simulator.app.workbuddy.host/?sharecode=VUYT4KG5HD
源码仓库：https://github.com/JohnnySilverhandV/LOL-S16-Champion-Simulator （码云同名仓库同步）

一、需求里藏着的三个难点

需求一句话：八强固定，用户猜四强、选赢家、调比分，最后决出冠军；点击对阵弹出 5v5 对位（上路 Theshy 对 369 这种）；界面要毛玻璃。

听起来像个静态页面，实际有三个难点：

  1. 级联一致性：改了四分之一决赛的比分，半决赛、决赛的参赛队伍必须跟着变——手工管理极易出现"前面改了后面没变"的脏数据
  2. 锁定与冲突：比分确认后要锁定防误改，但改上游比分可能悄悄改变某场已锁定比赛的参赛队伍
  3. 赛果与模拟的分离：真实比赛打完后（TES 1:3 IG），该场要从"模拟"变成"事实"，不可修改、重置也不能清掉

二、核心设计：buildState() 纯函数

整个淘汰赛是一棵树。我的方案是把"参赛队伍"从状态里拿掉，改为由比分实时推导：

const LINK = {qf1:["sf1",0], qf2:["sf1",1], qf3:["sf2",0],
              qf4:["sf2",1], sf1:["fin",0], sf2:["fin",1]};

function buildState(scores){
  const teams = {}, winners = {};
  for(const m of MATCHES){
    if(m.round === 0){
      teams[m.id] = m.teams.slice();          // 首轮种子固定
    }else{
      teams[m.id] = Object.entries(LINK)      // 下游队伍 = 上游胜者
        .filter(([, v]) => v[0] === m.id)
        .map(([src]) => winners[src] || null);
    }
    const [a, b] = scores[m.id] || [0, 0];
    const decided = a !== b && Math.max(a, b) >= WIN_TARGET;  // BO5：先到 3
    winners[m.id] = decided ? teams[m.id][a > b ? 0 : 1] : null;
  }
  return {teams, winners, champion: winners.fin || null};
}

state 里只存比分和锁定标记，队伍、胜者、冠军全部是比分 skyline 的投影。好处是数据永远自洽：不存在"比分改了队伍没跟上"的可能。

锁定冲突检测也顺理成章：确认比分前，用克隆的比分跑一遍 buildState，对比每场已锁定比赛的队伍是否变化——变了就拦截：

const built = buildState(JSON.parse(JSON.stringify(state.scores)));
for(const m of MATCHES){
  if(!state.locked[m.id] || m.id === curId) continue;
  if(JSON.stringify(state.teams[m.id]) !== JSON.stringify(built.teams[m.id])){
    warn.textContent = `${m.stage}已锁定，修改本场会改变其参赛队伍，请先解锁该场`;
    return;   // 拒绝写入
  }
}

三、官方赛果：事实和输入要分层

BO5 规则（先到 3、败方最多 2、杜绝 3:3）是第一版就写错的，这里给正确姿势：

const cap = other >= WIN_TARGET ? MAX_LOSE : WIN_TARGET;  // 对手到 3，我最多 2

真实比赛打完后，需求升级为"这场不能模拟了"。最初的锁定机制是用户可解锁的，官方赛果必须更强——放常量，不放存档：

/* 官方已完赛结果：不可模拟、不可解锁、重置也不清空 */
const FIXED = {
  qf1: [1, 3],   // teams 顺序是 ["TES","IG"] → TES 1 分，IG 3 分
};

function applyFixed(st){
  for(const id in FIXED){
    st.scores[id] = FIXED[id].slice();
    st.locked[id] = true;
  }
  return st;
}
let state = applyFixed(load() || blank());   // 每次加载都强制覆盖

加载时单向覆盖存档，老用户哪怕存过完全不同的比分，打开页面即被修正。后续每轮比赛打完，只需往 FIXED 加一行。

三层拦截缺一不可：不渲染比分按钮和解锁入口（而不是 disabled，避免"看起来能点"）、修改函数直接 return、弹窗文案明示"官方赛果不可修改"。视觉上官方完赛用青色边框 + 🏁，与手动锁定的金色 🔒 区分。

四、连接线：量布局画 SVG，别用 CSS 硬拼

轮次之间的晋级连线，正确做法是渲染完成后实测 DOM 坐标画肘形 path：

const ra = a.getBoundingClientRect(), rb = b.getBoundingClientRect();
const x1 = ra.right - wr.left, y1 = ra.top + ra.height/2 - wr.top;
const x2 = rb.left - wr.left,  y2 = rb.top + rb.height/2 - wr.top;
d += `<path class="link ${state.locked[src]?'active':''}"
       d="M${x1} ${y1} H${mx} V${y2} H${x2}"/>`;

窗口缩放时防抖 160ms 重绘。已锁定的晋级链路加 active 类点亮发光。这样列宽、卡片高度随内容变化都不会错位——伪元素拼边界那种写法，卡片一换行就露馅。

五、视觉细节里的两个坑

1. 纯黑文字在深色毛玻璃上会隐身。 用户要求 DK 队员名"黑色"，直接 color:#000 就是隐身。解法是加极细的浅色描边：

.p-name.dk-name{color:#0a0a0c;filter:drop-shadow(0 0 1.2px rgba(255,255,255,.65))}

2. 渐变文字加不了 text-shadow。 GEN 名字"左半暗黄右半黑"用 background-clip:text + color:transparent，此时 text-shadow 会失效（shadow 画在透明文字后面整个露出来），只能用 filter: drop-shadow()。

3. emoji 改不了色。 银色奖杯的需求，🏆 本身是金色 emoji，用滤镜转银：

.trophy{filter:grayscale(1) brightness(1.62) contrast(.92)
        drop-shadow(0 0 6px rgba(255,255,255,.55));}

六、发布：双仓库 + 三入口，一次做全

写完代码只是交付的一半，让不同渠道的读者都能打开才是完成态：

渠道 用途
WorkBuddy 托管 国内直连，发给朋友点开就玩
GitHub Pages 开发者入口，push 自动更新
GitHub + 码云 Release 双平台离线下载（各 5 个版本）

码云同步的配置：

git remote set-url --add --push origin <github-url>
git remote set-url --add --push origin <gitee-url>
git push origin main   # 一条命令推两边

两个真实坑：

  • GitHub 仓库名不支持中文：API 建 LOL-S16-冠军模拟器 返回 201，但 full_name 变成 LOL-S16--，中文字符被静默剔除，必须回读验证
  • 代理抖动时用 API 域名兜底：某天代理对 github.com 主站 CONNECT 成功率只剩 1/3，但 api.github.com 一直稳定——git push 走不通时，用 PUT /repos/{o}/{r}/contents/README.md 直接更新文件，再 fetch + rebase 收敛历史

七、可复用的结论

  1. 赛事模拟器通用骨架：固定首轮种子 + LINK 映射 + 纯函数级联重算，8 强/16 强/双败赛制都能套
  2. 派生数据不要存：队伍、胜者、冠军全部由比分推导，脏数据问题彻底消除
  3. 官方事实数据放常量、用户输入放存档，加载时单向覆盖
  4. 锁定冲突用纯函数试算，比事后回滚干净得多
  5. 发布渠道一次做全：托管链接给不折腾的用户，仓库给开发者，Release 给要离线的人
